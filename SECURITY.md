# Security Policy

## Maintenance policy

Security fixes are intended for the latest official release. Older releases
may not receive backported fixes. This is an experimental, independently
maintained project; no response deadline or guaranteed fix timeline is
promised.

## Reporting vulnerabilities

Do not publish exploit details, credentials, private recordings, webcam
captures, or other sensitive information in public issues or pull requests.

If the repository's Security tab offers Report a vulnerability, use that private
option. If it is unavailable, open an issue containing only a request for a
private security contact, without technical vulnerability details. Wait for the
maintainer to arrange a private channel before sharing sensitive information.

Once a private channel is established, provide the affected version,
installation source, potential impact, minimal safe reproduction steps, and
logs with private information removed. Please allow the maintainer an
opportunity to investigate before public disclosure.

## Safe use

Use official releases and trusted model sources. Do not load checkpoints,
weights, or executables supplied by unknown people. Do not submit real
credentials, OBS WebSocket passwords, or private conversations in reports.

Missed censorship, false vision blurs/triggers, and recognition errors are
generally accuracy bugs, not security vulnerabilities; use the bug report
template unless a separate security impact exists. Streamer Censoring
Multitool (SCM) is experimental and is not a guaranteed content-safety or
privacy safeguard.

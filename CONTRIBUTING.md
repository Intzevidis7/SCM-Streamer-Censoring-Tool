# Contributing to Streamer Censoring Multitool (SCM)

Created and maintained by Intzevidis7.

## License and authorization

Read LICENSE.md first. Streamer Censoring Multitool (SCM) uses a Custom Use
License, not a general open-source license. Repository access does not grant
permission to contribute code. Code contributions require prior written
permission from Intzevidis7 and a separate contributor agreement, as
specified in LICENSE.md. Do not begin source changes or submit a code pull
request before obtaining that permission.

## Bug reports and suggestions

Bug reports, usability feedback, and feature suggestions are welcome. Search
existing issues and use the appropriate template. Include app and Windows
versions, installation source, reproduction steps, expected and actual
behavior, and relevant log excerpts. For audio or vision problems, include
input/output devices, recognition mode, AI detector setting, delay, device
sample rates if known, OBS routing/camera source details, and vision guard
settings.

Redact personal information, private paths, and sensitive conversations. Do
not upload recordings, datasets, checkpoints, caches, or executables without
prior agreement. Share only materials you have permission to share.

## Approved code contributions

If explicitly authorized under the required contributor agreement:
1. Agree on scope and target branch before starting.
2. Keep changes focused and preserve credits, licenses, and notices.
3. Keep models, datasets, recordings, caches, settings, credentials, and build outputs out of commits.
4. Describe tests honestly, including tests not performed.
5. Test audio and vision changes using a local recording before any live use and document relevant settings.
6. Use the pull request template.

Approval of a proposed change does not grant permission to redistribute or
reuse the project outside the applicable written agreement.

Follow CODE_OF_CONDUCT.md. For potential vulnerabilities, follow SECURITY.md
rather than posting sensitive details publicly.
